## 🚀 Быстрый старт (5 минут)

### Вариант 1: Использовать SQLite (Рекомендуется для начала)

SQLite не требует установки PostgreSQL и работает без интернета.

```powershell
# 1. Перейти в backend
Set-Location "d:\QR MENU\backend"

# 2. Переименовать .env файлы
Rename-Item .env .env.Render PostgreSQL
Rename-Item .env.local .env

# 3. Переименовать schema файлы
Set-Location prisma
Rename-Item schema.prisma schema.postgres.prisma
Rename-Item schema.local.prisma schema.prisma

# 4. Создать базу данных
Set-Location ..
npx prisma db push

# 5. Создать тестовые данные
node prisma/seed.js

# 6. Запустить проект
Set-Location "d:\QR MENU"
npm run dev
```

**Готово!** Теперь можете войти с тестовыми данными:

- Email: `test@restaurant.com`
- Password: `test123`

## 🔄 Переключение между SQLite и Render PostgreSQL

### Переключиться на SQLite (локальная разработка)

```powershell
Set-Location "d:\QR MENU\backend"

# Переключить .env
Rename-Item .env .env.Render PostgreSQL -Force
Rename-Item .env.local .env -Force

# Переключить schema
Set-Location prisma
Rename-Item schema.prisma schema.postgres.prisma -Force
Rename-Item schema.local.prisma schema.prisma -Force
Set-Location ..

# Применить схему
npx prisma db push
```

### Переключиться на Render PostgreSQL (production)

```powershell
Set-Location "d:\QR MENU\backend"

# Переключить .env
Rename-Item .env .env.local -Force
Rename-Item .env.Render PostgreSQL .env -Force

# Переключить schema
Set-Location prisma
Rename-Item schema.prisma schema.local.prisma -Force
Rename-Item schema.postgres.prisma schema.prisma -Force
Set-Location ..

# Применить миграции
npx prisma db push
```

## 📊 Различия между SQLite и PostgreSQL

| Функция            | SQLite                     | PostgreSQL (Render PostgreSQL)   |
| ------------------ | -------------------------- | ----------------------- |
| Установка          | ❌ Не требуется            | ✅ Требуется / Cloud    |
| Интернет           | ❌ Не требуется            | ✅ Требуется            |
| Производительность | ⚡ Быстрая для разработки  | 🚀 Лучше для production |
| Массивы            | ❌ Нет (используем JSON)   | ✅ Есть                 |
| Enum типы          | ❌ Нет (используем String) | ✅ Есть                 |
| Подходит для       | 🏠 Локальная разработка    | 🌐 Production           |

## ⚠️ Важно

### SQLite ограничения

1. **Массивы**: В PostgreSQL `banners String[]`, в SQLite `banners String` (JSON строка)
2. **Enum**: В PostgreSQL `SubscriptionPlan`, в SQLite `String`

### Код должен работать с обоими

Backend код уже адаптирован для работы с обоими типами БД.

## 🐛 Решение проблем

### Ошибка: "Can't reach database server"

**Причина**: Пытаетесь подключиться к Render PostgreSQL, но нет интернета или неверные учетные данные.

**Решение**: Переключитесь на SQLite (см. выше)

### Ошибка: "Table does not exist"

**Причина**: База данных не создана.

**Решение**:

```powershell
Set-Location "d:\QR MENU\backend"
npx prisma db push
node prisma/seed.js
```

### Ошибка: "Invalid credentials"

**Причина**: Нет тестовых данных в БД.

**Решение**:

```powershell
Set-Location "d:\QR MENU\backend"
node prisma/seed.js
```

### Ошибка: "banners.map is not a function"

**Причина**: В SQLite массивы хранятся как JSON строки.

**Решение**: Уже исправлено в коде! Backend автоматически парсит JSON строки в массивы. Если ошибка всё ещё появляется:

1. Перезапустите сервер (Ctrl+C и `npm run dev`)
2. Очистите кэш браузера (Ctrl+Shift+R)

## 🔧 Вариант 2: Установить PostgreSQL локально

Если хотите полную совместимость с production:

### Установка PostgreSQL

1. Скачать: https://www.postgresql.org/download/windows/
2. Установить с настройками по умолчанию
3. Запомнить пароль для пользователя `postgres`

### Настройка

```powershell
# Создать базу данных
psql -U postgres
CREATE DATABASE oimoqr_dev;
\q

# Обновить .env
# DATABASE_URL="postgresql://postgres:ВАШ_ПАРОЛЬ@localhost:5432/oimoqr_dev"

# Применить миграции
Set-Location "d:\QR MENU\backend"
npx prisma db push
node prisma/seed.js
```
